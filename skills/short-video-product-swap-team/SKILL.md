# 短视频产品替换团队

使用稳定英文 ID 调度角色，所有面向用户的名称、状态和交付文档使用中文。先读取 [团队角色](references/team-roles.md)，再根据任务阶段读取相应流程。

## 首轮需求确认卡（强制）

收到新素材或新项目后，先不要抽帧、改图或提交生成。先用中文确认：

1. **替换对象**：产品、人物、场景/背景、道具/包装、文案/对白、字幕或其他对象；多项时逐项列出。
2. **保留对象**：人物身份、脸部、手部、服装、动作、机位、构图、背景、光线和节奏。
3. **声音与文字**：保留原音、模型直接生成音频或后期配音；字幕保留、清除或按新文案生成。
4. **参考方式与输出**：是否上传参考视频，目标模型、时长、分辨率、画幅，以及直接生成/手动素材包。

确认卡后，针对素材主动给出 2–4 条建议和风险提示。用户确认替换范围及关键建议后，才开始拆解、改图、定价和生成。若用户已明确相关信息，整理回显确认即可，不重复追问。

## 工作原则

- 原始参考视频默认只在本地分析。外部视频模型只接收审核后的提示词、三联关键帧和产品图。
- API 生成必须把已审核的逐镜复刻蓝图编入提示词；关键帧只作视觉证据，不可用泛化的“保留动作/节奏”代替镜头时间、动作、构图、机位、切点和连续性描述。
- 逐镜框架里仍有“待分析/待补充/TODO”等占位内容时，停止付费提交，先补做视觉拆解与复核。
- 只允许在明确列出的替换字段改产品和文案；镜头顺序、场景、动作、产品呈现方式、机位、构图和节奏沿用拆解。文案改写要按原时间轴逐段映射。
- 音频按用户要求设置；用户要求口播时使用 `voiceover` 或 `full`，不得套用静音模板或“生成无声视频”旧提示。
- 保留人物身份、脸部、服装、动作、机位、构图、场景和节奏，只替换用户指定产品。
- 关键帧默认每秒抽一帧；默认每三张连续帧横向拼图，也支持每六张连续帧按 3 列 × 2 行拼图；`Shot 01` 起全局连续编号，不按拼图重置。
- 使用图像模型逐帧替换产品、人物或场景时，每 6 张连续抽帧制作一张带全局编号的 3 列 × 2 行拼图作为上下文参考；实际编辑必须以单张原始帧为底图，拼图只提供场景、构图、动作及跨帧连续性，替换对象参考图提供外观依据。只改用户指定对象，保留其他画面区域、遮挡、姿态、构图与光线；先做一张代表帧并验收，再批量处理。
- 真实生成前必须展示模型、时长、分辨率、参考素材数量和预计费用。没有明确费用确认时，只执行本地处理、dry-run、`check`、`plan` 和 `pricing`。
- 每次都准备两种交付：直接生成成片，以及可供其他平台使用的 ZIP 素材包和中文教程。
- 使用 `video-replicator replication-prompt` 从 `replication-framework.json` 和 `script-timeline.json` 编译 API 提示词；编译器会阻止未完成的镜头字段和无效时间轴。
- 真实提交前必须存在审核后的 `analysis/replication-framework.json`、编译后的 `outputs/final_product_swap_prompt.md` 和 `outputs/qa.json`（状态为 `approved`）；Hypit provider 当前不支持原生音频。
- 密钥只保存在 Credential Store 或本机环境文件中，不进入代码、运行时 JSON、日志、截图或 Git。

## 路由

- 新项目、完整复刻或继续现有项目：读取 [完整工作流](references/workflow.md)。
- 对接第三方 API、切换模型、直接生成或手动交付：读取 [生成与交付](references/provider-and-delivery.md)。
- 仅需重新抽帧：执行工作区的 `video-replicator keyframes`，不要上传原视频。
- 仅需检查环境：优先执行工作区的 `scripts/diagnose-workspace.ps1`，不得通过真实生成任务测试连接。

## 完成标准

交付前确认：项目报告可继续接手；三联图与 manifest 一致；提示词明确只替换产品；付费审批有记录；成片已观看；人物、产品、时长、音轨和字幕状态写入验收报告；ZIP 包不含密钥或原视频。
