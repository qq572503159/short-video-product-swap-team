# 完整工作流

## 1. 首轮需求确认与边界

收到素材后先发需求确认卡，确认替换对象、必须保留对象、音频/字幕策略、是否上传参考视频、模型与画幅时长、交付方式。根据素材主动给出 2–4 条建议和风险。用户确认替换范围后再开始拆解；已明确的信息整理回显，不重复追问。确认用户对参考素材和产品素材具有使用权限。

## 2. 本地拆解

使用工作区 CLI 的 `team-run` 或依次执行 `analyze`、`keyframes`、`plan`、`prompts` 和 `qa`。原视频不上传。分析产物写入项目的 `analysis/` 和 `outputs/`，不要由后续角色反向覆盖。

## 3. 三联关键帧

候选帧不足时使用 ffmpeg 每秒补抽一帧。按时间排序，默认每三张连续帧拼图，也可用每六张连续帧的 3 列 × 2 行拼图；编号全局递增，不按拼图重置。拼图是时间证据，不代表最终三分屏或六格布局。模型参考图数量不足时优先选首段、中段和尾段拼图，再加入产品图。

## 3A. 逐帧图像替换（产品/人物/场景）

- 将抽帧按时间排序，每 6 张组成一张带全局编号的 3 列 × 2 行参考拼图；末组保留实际帧数，不复制或重编号。拼图仅提供场景、构图、动作和跨帧连续性上下文。
- 拼图不能作为编辑结果的底图，否则模型可能重绘拼图布局或把多个时刻合并。每次以需要修改的单张原始帧为编辑底图，并把对应拼图、目标对象参考图作为额外参考输入。
- 明确唯一修改对象及不变量：替换产品时保留人物、手部和场景；替换人物时保留场景、机位、构图与动作关系；替换场景时保留主体身份、姿态、比例和边缘遮挡。匹配透视、尺度、光线、色彩和接触阴影。
- 按用户要求清除烧录字幕、促销文字、水印等覆盖层；不要把拼图编号或格线带入编辑结果。先做一张代表帧测试，检查替换对象、保留区域、遮挡/边缘和文字，再经用户确认后批量处理。
- 必须像素级不变的区域不能只靠提示词保证；使用蒙版/合成并人工核验。生成后的逐帧图须通过时间连续性检查，之后才重新拼图或交给视频模型。

## 4. 逐镜复刻蓝图与提示词

先把真实镜头边界和镜头内动作阶段整理为 `replication-framework.json`。逐镜写明时间、对应关键帧编号、场景、景别/构图、动作起止、机位/运镜、连续性。只把经人工核对的可观察事实放进蓝图；无法确认的内容要标记并补看，不以概括性形容词代替。

用 `video-replicator replication-prompt --framework ... --timeline ... --output ... --audio-mode ...` 编译提示词。编译器会把产品/文案作为独立替换层，同时保留逐镜骨架；框架占位、时间越界或镜头重叠会阻止编译。明确写出连续单画面、编号拼图只作时间参考、产品图锁定产品外观、原烧录字幕/促销覆盖层需清除。

## 5. 生成前验收

检查三联图、产品图、时长、画幅、音频策略、公开 URL 和脱敏日志。`qa.status=review_required` 时保留 flags，并要求负责人处理或明确批准，不能静默提交。

## 6. 生成与合成

音频按用户指定模式生成：用户要求口播时提示词必须带逐段改写文案并开启同步生成音频；只有用户明确要求静音时才关闭声音。视频模型输出后检查音轨实际存在、人物/手部、产品瓶型与标签、场景变化、动作连续性、字幕和画幅。不要仅凭任务状态 `completed` 判定成片合格。

## 7. 双交付

直接生成路线交付成片和验收报告。手动路线交付三联图、产品图、提示词、参数、原音轨、本地合并脚本和中文教程。ZIP 中不得包含 API key 或原始参考视频。
